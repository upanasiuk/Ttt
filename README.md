# 📦 Трекер посылок — Текущее состояние проекта

## 🛠 Стек технологий
*   **Бэкенд:** Python 3.13 (FastAPI, SQLite, PyJWT, pwdlib, openpyxl).
*   **Фронтенд:** Vanilla JS (без фреймворков), CSS3, HTML5, PWA (Service Worker, Manifest).
*   **Библиотеки (CDN):** ZXing (v0.23.0) для сканирования штрихкодов.
*   **Контейнеризация:** Docker, Docker Compose.

---

## 👥 Ролевая модель
1.  **Гость:** 
    *   Видит только экран входа. 
    *   Если система пустая — экран первичной настройки (создание Главного админа).
2.  **Пользователь (Юзер):** 
    *   Не имеет доступа к чужим трекам.
    *   Видит только свои партии и свои треки.
    *   Имеет доступ к вкладке «Моя статистика».
    *   Не может сканировать, добавлять или редактировать треки.
3.  **Администратор (обычный):**
    *   Может создавать/редактировать/удалять партии.
    *   Может добавлять/редактировать/удалять треки.
    *   Имеет доступ к сканеру.
    *   Может выдавать/отзывать права администратора другим пользователям.
    *   **НЕ МОЖЕТ** менять пароли другим пользователям.
    *   **НЕ МОЖЕТ** удалять пользователей (кнопки скрыты в UI, API возвращает 403).
4.  **Главный администратор (Super Admin):**
    *   Это пользователь с `id = 1` (тот, кто первый настроил систему).
    *   Имеет полные права, как обычный админ.
    *   **Может** менять пароли всем пользователям.
    *   **Может** удалять пользователей (кроме себя).

## 🎨 Интерфейс и UX/UI (Фронтенд)
*   **Вкладки:**
    *   **Сканер:** Доступен только админам. Включает камеру, распознает штрихкоды, показывает карточку трека, позволяет выдавать (статус `issued`) и взвешивать.
    *   **Партии:** 
        *   Поиск с фильтрацией (Везде / Название / Получатель / Трек).
        *   Пагинация (5 / 25 / 50 элементов).
        *   Спойлер «Активные партии» (по умолчанию скрыт).
        *   Кнопки в карточке партии: `[Выбрать]` (оранжевая), `[Закрыть/Открыть]`, `[Экспорт]` (зеленая), `[Удалить]` (красная).
        *   Архив закрытых партий.
        *   Добавление трека (с раскрывающимся полем для штрихкода).
        *   Поиск по трекам выбранной партии.
    *   **Все треки:** Поиск, фильтр по статусу, пагинация.
    *   **Получатели (только админ):** Форма добавления, список с тумблерами «Админ», кнопками «Сменить пароль» и «Удалить» (для Главного админа).
    *   **Моя статистика (только юзер):** Сводка по весу, цене и количеству выданных/невыданных треков.
*   **Визуальные фишки:**
    *   **Тёмная тема:** Основной фон `#0f172a`, карточки полупрозрачные (`rgba`), акценты оранжевые (`#f59e0b`) и красные (`#ef4444`).
    *   **Тосты (Уведомления):** Всплывают в правом нижнем углу при успешном добавлении трека, сохранении изменений, выдаче и т.д.
    *   **Модалка удаления:** Красная (рамка, заголовок, кнопка), требует ручного ввода названия для подтверждения (защита от случайных кликов). В поле ввода серый плейсхолдер с названием.
    *   **Кнопка-ссылка:** Если у трека есть URL, рядом со статусом появляется аккуратная оранжевая квадратная кнопка со стрелочкой `↗`.
    *   **Автовыделение:** При клике на поле количества (в распределении) число выделяется автоматически.
    *   **Подсветка текста:** Выделенный текст (и цифры) подсвечивается оранжевым.

## ⚙️ Бэкенд и логика
*   **Сессии:** JWT-токены (PyJWT). Живут 24 часа (настраивается в `.env` через `ACCESS_TOKEN_EXPIRE_MINUTES`). Работает «скользящее окно» (при активности токен продлевается). Если 24 часа ничего не делать — разлогин.
*   **Пароли:** Хэшируются через `pwdlib` (Argon2).
*   **Расчет цен:** В статистике юзера и админа цена трека делится пропорционально количеству, которое взял конкретный получатель. В карточке редактирования показывается полная цена трека (чтобы не сломать данные при сохранении).
*   **Экспорт в Excel:** Выгружает только треки со статусом `received_cargo`. Группирует одинаковые товары, считает общую сумму.
*   **Сканер:** Работает через ZXing, при успехе отправляет запрос `/api/scan`, получает ID, находит трек и показывает карточку.
*   **Очистка полей:** В `update_track` разрешено стирать поля (отправлять `null` или пустые строки), старые данные не «залипают».

## 🗄 База данных (SQLite)
*   `recipients` (id, name, username, password_hash, is_admin, is_deleted)
*   `parcels` (id, name, is_active, status, created_at, completed_at)
*   `tracks` (id, barcode, parcel_id, attachment, quantity, unit, price, weight_g, comment, url, status, issued_at, created_at)
*   `track_allocations` (track_id, recipient_id, quantity) — связь треков и получателей с указанием доли.
